# Source request policy

`validateConfiguration` produces an immutable configuration for the exact intake scope: `To == 2026` and ending years 2022 through 2026. It validates the provider, host allowlist, storage, parser versions, claim timeout, GET method, HTTPS scheme, manual redirects, and the request policy. The Fetcher validates the same request policy when constructed directly.

Requests are sequential per host, at least six seconds apart, and limited to ten starts per minute. The policy includes a whole-request timeout, bounded redirect count, maximum attempts, bounded exponential retry delay, a response-byte limit (16 MiB by default), a maximum accepted `Retry-After` (24 hours by default), and optional cache freshness. The transport receives `timeoutMs` and `maxResponseBytes`; it must finish or cancel the socket before returning. The Fetcher renews the job claim while a request is active. Request ownership is released only when the socket settles. Redirects acquire ownership and apply pacing for each destination host parsed from the URL.

A fresh, checksum-verified cache entry can be reused without transport, except when the prior response declares `no-cache` or `no-store`. An upstream `max-age` can shorten the configured cache age. `no-cache` still permits a conditional request; `no-store` forces an unconditional request. Stale entries send available ETag and Last-Modified validators. A 304 requires a conditional request, reuses the verified immutable body, and records a new fetch without a new raw object. Cache hits also record a fetch with `cache_hit = true` and `reused_body = true` so their synthetic 200 status is distinguishable from a network response.

A 429 with a valid `Retry-After` delays at least the minimum interval. Missing, invalid, or excessively long values stop for operator review; the worker never retries earlier than the provider requested merely to fit the configured cap. 403 and recognized challenge pages stop for review. 5xx, socket resets, and timeouts use bounded exponential backoff. Timeout uses the typed `transport_timeout` code while retaining the existing `retry_wait` or `permanently_failed` job states. TLS, DNS-policy, unsupported-encoding, and oversized-body failures stop for review rather than retrying.

The real transport uses HTTPS with certificate verification, manual redirects, no ambient proxy, identity content encoding, and a streaming byte limit. Before connecting, it resolves every address, rejects non-public addresses, and pins a validated address to the connection. The local TLS tests inject a loopback-only address policy and trust a test certificate; production defaults do neither. The fixture transport remains explicit in local mode. Worker mode still requires a configured production source adapter and authorization before crawling.
